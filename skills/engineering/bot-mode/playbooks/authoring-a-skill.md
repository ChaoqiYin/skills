# Authoring a skill

Use for creating, revising, or evaluating skill instructions. Locate available authoring guidance through the current agent's catalog.

1. Read the reference or existing skill, project conventions, and intended requests. Preserve unrelated behavior and files. Create a skill only when requested or required by the authorized task.
2. Use the requested project path. If discovery is required, identify a recognized skill location through catalog metadata and documented discovery rules.
3. Write a specific name and description. Keep common decisions in `SKILL.md` and substantial conditional procedures in linked references. Preserve the requested invocation policy and use supported metadata.
4. Describe delegation through available subagent tools using environment defaults. Access history through supported interfaces or documented sources. Avoid fixed model rules and assumptions about another environment's capabilities.
5. Check frontmatter, paths, discovery, and dependencies. Read routed skills before describing their behavior. Distinguish advice, read-only work, execution, and authorized external actions.
6. Check realistic requests, an unavailable capability, and a request outside the skill's scope. Use an available validator. Run independent evaluation only when warranted and authorized, using isolated inputs. Otherwise describe verification as structural checks and scenario inspection.

Update required project indexes. Return the skill paths and checks completed. Install globally, change other configuration, or open a PR only when the task includes those actions.
